# Платформенный слой: единый интерфейс + модули по ОС/DE

## Цель

Задел на будущее: разные модули в зависимости от ОС (Linux / Windows / macOS) и окружения (KDE / GNOME) за **единым интерфейсом**. Полная поддержка — только **Kubuntu (Linux + KDE Plasma)**. Остальные — заглушки с внятным `Unsupported`.

**Масштаб (подтверждён):** только платформенный слой. Domain / app / use-cases / UI не переписываем. Порты в `switchfix-app/src/ports.rs` остаются единым интерфейсом по возможностям.

**Выбор модуля:** `cfg(target_os)` — ОС; runtime-детект DE (`XDG_CURRENT_DESKTOP`) — KDE vs GNOME внутри Linux.

## Текущее состояние (факты)

- 8 портов уже есть: `TextInjector`, `ClipboardPort`, `SelectionCapture`, `TypingBufferPort`, `LayoutSwitcher`, `HotkeySource`, `ConfigStore`, `Notifier` (`crates/switchfix-app/src/ports.rs`).
- `wiring.rs` жёстко собирает стек KDE: `KdeLayoutSwitcher` → `UinputInjector` → `WaylandClipboard` → `EvdevHotkeySource` → `CorrectionService`. Падает с «Are you on KDE Plasma?» без `org.kde.keyboard`.
- **Нет ни одного `cfg(target_os)`**. Linux-зависимости (`evdev`, `zbus`, мёртвый `wl-clipboard-rs`) объявлены безусловно.
- Детекта DE нет (только информационный `XDG_*` в `doctor.rs`).
- UI уже ходит через порты (`Box<dyn ConfigStore>`), tray (ksni/SNI) — не трогаем.
- Тестов **76 зелёных** — должны остаться.

## Подход

Классический OOP на Rust: **Strategy + Abstract Factory**.

- `Platform` — единый интерфейс (trait) платформы.
- `KdePlatform` / `GnomePlatform` / `WindowsPlatform` / `MacosPlatform` — модули-реализации.
- `create_platform()` — фабрика: compile-time ОС + runtime DE.
- `PlatformServices` — набор `Arc<dyn Port>` на все 8 портов (фасад над существующими портами).

Порты не меняем — они уже и есть «единый interface» по возможностям. `Platform` — единая точка входа для **сборки** платформенных реализаций.

## Целевое дерево модулей

```
crates/switchfix-adapters/src/
  lib.rs                      # pub mod platform; реэкспорт только портируемого
  platform/
    mod.rs                    # Platform, PlatformInfo, PlatformServices, PlatformError,
                              # OsKind, DesktopKind, SessionKind
    detect.rs                 # detect_os/de/session, parse_desktop()
    factory.rs                # create_platform() -> Box<dyn Platform>
    portable/                 # общее для всех ОС
      mod.rs
      typing_buffer.rs        # SharedTypingBuffer (из evdev_hotkey.rs)
      config_store.rs         # TomlConfigStore (перенос)
      clipboard.rs            # ArboardClipboard (перенос, rename WaylandClipboard)
      manual_hotkeys.rs       # ManualHotkeySource (перенос)
    linux/
      mod.rs                  # общий Linux-код + реэкспорт
      evdev_hotkey.rs         # EvdevHotkeySource (перенос)
      uinput_injector.rs      # UinputInjector (перенос)
      kde/
        mod.rs                # KdePlatform
        layout.rs             # KdeLayoutSwitcher (перенос kde_layout.rs)
      gnome/
        mod.rs                # GnomePlatform — заглушка
    windows/
      mod.rs                  # WindowsPlatform — заглушка (cfg)
    macos/
      mod.rs                  # MacosPlatform — заглушка (cfg)
```

Старые файлы `clipboard.rs`, `config_store.rs`, `evdev_hotkey.rs`, `kde_layout.rs`, `uinput_injector.rs` удаляются после переноса (без дублей).

## API платформы (сигнатуры)

```rust
// platform/mod.rs
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum OsKind { Linux, Windows, Macos, Unknown }

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum DesktopKind { Kde, Gnome, Other, Unknown }

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum SessionKind { Wayland, X11, Unknown }

#[derive(Debug, Clone)]
pub struct PlatformInfo {
    pub os: OsKind,
    pub de: DesktopKind,
    pub session: SessionKind,
    pub de_raw: String,      // XDG_CURRENT_DESKTOP как есть (для doctor)
    pub session_raw: String,
}

pub struct PlatformServices {
    pub injector: Arc<dyn TextInjector>,
    pub clipboard: Arc<dyn ClipboardPort>,
    pub selection: Arc<dyn SelectionCapture>,
    pub buffer: Arc<dyn TypingBufferPort>,
    pub layouts: Arc<dyn LayoutSwitcher>,
    pub hotkeys: Box<dyn HotkeySource>,
    pub config: Arc<dyn ConfigStore>,
    pub notifier: Arc<dyn Notifier>,
}

#[derive(Debug, thiserror::Error)]
pub enum PlatformError {
    #[error("unsupported OS: {os:?}")]
    UnsupportedOs { os: OsKind },
    #[error("unsupported desktop: {de:?} — {reason}")]
    UnsupportedDesktop { de: DesktopKind, reason: String },
    #[error("{component}: {message}")]
    Init { component: &'static str, message: String },
}

#[async_trait]
pub trait Platform: Send + Sync {
    /// Стабильный id: "linux/kde", "linux/gnome", "windows", "macos".
    fn id(&self) -> &'static str;
    fn info(&self) -> &PlatformInfo;
    /// false = заглушка (нет полной реализации).
    fn is_supported(&self) -> bool;
    /// Сборка всех платформенных реализаций портов.
    async fn build_services(&self, cfg: &AppConfig)
        -> Result<PlatformServices, PlatformError>;
}
```

```rust
// platform/detect.rs
pub fn detect() -> PlatformInfo;
pub fn parse_desktop(raw: &str) -> DesktopKind; // "KDE", "ubuntu:GNOME", "GNOME"…
```

```rust
// platform/factory.rs
pub fn create_platform() -> Box<dyn Platform>;
// cfg(target_os="linux") + match detect().de:
//   Kde   -> KdePlatform      (полная)
//   _     -> linux::GnomePlatform / UnsupportedDesktopPlatform
// cfg(target_os="windows") -> WindowsPlatform (заглушка)
// cfg(target_os="macos")   -> MacosPlatform   (заглушка)
// иначе                   -> UnsupportedOsPlatform
```

Заглушки возвращают `Box<dyn Platform>` с `is_supported() == false` и
`build_services() -> Err(PlatformError::Unsupported…)` с текстом-подсказкой
(«GNOME: ожидается в фазе 5, используйте KDE» / «Windows: не поддерживается»).

## Поведение KdePlatform::build_services

Переиспользует текущие адаптеры практически как есть:

| Порт | Реализация | Примечание |
|------|-----------|------------|
| `TextInjector` | `UinputInjector` | как сейчас, ошибка Init с hint про `input` |
| `ClipboardPort` + `SelectionCapture` | `ArboardClipboard` (ex `WaylandClipboard`) | один экземпляр, два `Arc`-представления (как в wiring.rs:180–181) |
| `TypingBufferPort` | `portable::SharedTypingBuffer` | параметры из `cfg.privacy` |
| `LayoutSwitcher` | `KdeLayoutSwitcher` | zbus `org.kde.keyboard`, camelCase |
| `HotkeySource` | `EvdevHotkeySource`, fallback `ManualHotkeySource` | bindings из `cfg.hotkeys`, `hotkey_consume` |
| `ConfigStore` | `portable::TomlConfigStore` | |
| `Notifier` | `portable::LogNotifier` (перенести из wiring.rs) | |

Второй `UinputInjector` для clipboard — внутри `KdePlatform` (как сегодня в wiring.rs:113–119).

## Cargo.toml

- `crates/switchfix-adapters/Cargo.toml`:
  - `evdev`, `zbus` → `[target.'cfg(target_os = "linux")'.dependencies]`
  - **удалить** мёртвый `wl-clipboard-rs`
  - `arboard`, `dirs`, `toml`, `uuid` — безусловно (portable)
- Остальные crate — без изменений (или только path-реэкспорты, если сломается `lib.rs`).

## Изменения в daemon

1. **`wiring.rs`** — composition root упрощается:
   - `let platform = platform::create_platform();`
   - `let services = platform.build_services(&cfg).await?;`
   - `CorrectionService::new(services.injector, services.clipboard, services.selection, …)`
   - `LogNotifier` уезжает в `platform/portable`.
   - `WireOptions` сохраняем (для тестов/отладки).
2. **`doctor.rs`** — добавить блок «Platform»: `platform.id()`, `os`, `de`, `session`, `is_supported`. Существующие Linux-пробы оставить.
3. **`setup.rs`** — не трогаем (Linux-only утилита).

## Что НЕ меняем

- `switchfix-domain`, `switchfix-app` (сигнатуры портов, `CorrectionService`, config, hotkey)
- `switchfix-ui` (tray ksni, settings iced)
- `switchfix-tests` (fakes и сценарии — ходят через порты)
- packaging, docs (кроме опциональной строки в PLAN.md про платформенный слой)
- Реальную GNOME/Windows/macOS-реализацию

## Юнит-тесты (новые)

В `platform/detect.rs` / `factory.rs` (или `platform/mod.rs` tests):

1. `parse_desktop`: `"KDE"` → Kde, `"kde"` → Kde, `"ubuntu:GNOME"` → Gnome, `"GNOME"` → Gnome, `"X-Cinnamon"` → Other, `""` → Unknown, `"KDE;GNOME"` → Kde (первый).
2. `detect_os()` на текущей машине → `Linux`.
3. `create_platform().id() == "linux/kde"` (на Kubuntu) / `is_supported() == true` только для KDE; для подменённого `de_raw` — заглушка (через `parse_desktop` + match, без env-моков, если возможно — вынести `select_platform(info) -> Box<dyn Platform>` и тестировать её).
4. Заглушка: `build_services()` возвращает `Unsupported*`.

Существующие 76 тестов не трогать; после рефактора прогнать `cargo test --workspace`.

## Порядок реализации (дерево компилируется после каждой фазы)

1. **Каркас платформы** — `platform/{mod,detect,factory}.rs` + `portable/` (перенос `SharedTypingBuffer`, `TomlConfigStore`, clipboard, `ManualHotkeySource`, `LogNotifier`). Старые пути оставить re-export `#[deprecated]` или сразу обновить `lib.rs`. Компилируется.
2. **Linux-модули** — перенос `evdev_hotkey`, `uinput_injector` в `platform/linux/`, `kde_layout` → `linux/kde/layout.rs`. `KdePlatform::build_services`. Обновить `wiring.rs` на фабрику. Тесты зелёные.
3. **Заглушки** — `linux/gnome`, `windows`, `macos` + cfg-декорации в Cargo.toml. `select_platform`/`create_platform`.
4. **Doctor + полировка** — печать `PlatformInfo`; удалить остатки старых путей; `cargo test --workspace`; `./target/release/switchfix doctor` на живой KDE-сессии.

## Риски / подводные камни

- **`evdev::KeyCode` в публичном API** (`key_name_to_code`) — оставить внутри `platform/linux`, не реэкспортировать наружу.
- **Дубль буфера**: adapters `SharedTypingBuffer` vs domain `TypingBuffer` — в рамках задачи только переносим adapters-копию в `portable/`, не унифицируем (вне scope).
- **`KeyChord`** — конкретные аккорды (`CtrlInsert` и т.п.) остаются в domain; на Windows/macOS потом нужен маппинг — не сейчас.
- **Перенос файлов** может сломать `use` в tests/doctor — проходиться по `cargo build --workspace` после каждой фазы.
- **`WaylandClipboard` rename** → `ArboardClipboard`: затронет `lib.rs` re-export и `wiring.rs`; имя честнее (arboard, не wl-clipboard-rs).
- Заглушки должны **компилироваться** только на своей ОС (`cfg`), иначе Linux-сборка не пройдёт из-за отсутствия winapi/cocoa.
