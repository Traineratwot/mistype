# Кнопки «Редактировать конфиг» / «Перезагрузить конфиг» + настраиваемые карты

## Цель

В окне настроек:
1. **«Редактировать конфиг»** — открыть `~/.config/switchfix/` в файловом менеджере (видно `config.toml` и `maps/`).
2. **«Перезагрузить конфиг»** — перечитать файл в форме и подать сигнал работающему демону.

Ручная настройка:
- **карты раскладок** — JSON в `~/.config/switchfix/maps/` (seed при первом запуске, дальше только правка руками);
- **`behavior.terminal_apps` / `excluded_apps`** — только через `config.toml` (UI-списков нет).

Хоткеи по-прежнему требуют **рестарт демона** (MVP, не меняем).

---

## Решения

| Вопрос | Решение |
|--------|---------|
| Карты | `~/.config/switchfix/maps/{en2ru,ru2en}.json`, формат `MapFile` уже в domain |
| Seed | При startup/settings: записать дефолты **только если каталог пуст/отсутствует**; правки не затирать; удалённые файлы не воскрешать |
| Reload UI | `store.load()` → форма + флаг `switchfix.reload` |
| Reload daemon | Флаг `$TMPDIR/switchfix.reload` (token = timestamp) в существующем 2s poll + `config_tx.send` + `replace_tables` |
| Хоткеи | Не трогаем; статус/лог «после перезапуска демона» |
| UI-список терминалов | Не делаем (по выбору пользователя) |
| Открытие конфига | `xdg-open ~/.config/switchfix/` |
| ConfigStore trait | **Не расширяем** — `run_settings(store, config_dir: PathBuf)` |
| Source seed maps | `serde_json` из domain `MapFile` / `en_to_ru_map()`, **не** `include_str!` (хрупкие относительные пути) |

## Изменения по файлам

### 1. Новый `crates/switchfix-adapters/src/platform/portable/maps.rs`

```rust
pub fn user_maps_dir() -> PathBuf;                 // dirs::config_dir()/switchfix/maps
pub fn seed_default_maps() -> std::io::Result<()>; // write-if-dir-empty
pub fn load_conversion_set() -> ConversionSet;     // parse *.json; invalid → skip+warn; empty → en_ru()
```

- Seed: `MapFile { name, from, to, map }` из `en_to_ru_map()` + `.reverse()`, `serde_json::to_string_pretty`.
- `load_conversion_set`: только `*.json`; битый файл — warn + skip; если ни одной валидной таблицы → `ConversionSet::en_ru()`.
- Re-export: `platform/portable/mod.rs`, `switchfix-adapters/src/lib.rs`.

### 2. `crates/switchfix-app/src/services/correction.rs`

```rust
// было: tables: ConversionSet,
tables: std::sync::RwLock<ConversionSet>,

pub fn replace_tables(&self, tables: ConversionSet);
```

- Кторы `new`/`with_focus` — сигнатуры без изменений (кладут `ConversionSet` в `RwLock`).
- Call sites `convert(&text, &self.tables, …)` → короткий read-guard **только** на время синхронного `convert`, **не** держать через `.await`.
- Domain не трогаем (чистый).

### 3. `crates/switchfix-ui/src/settings_app.rs`

- `Message::OpenConfigFolder`, `Message::ReloadConfig`.
- `run_settings(store, config_dir: PathBuf)` — UI не зависит от adapters.
- Футер в две строки (ширина окна 580):
  1. `Сохранить | Перезагрузить конфиг | Закрыть`
  2. `Редактировать конфиг` + `status`
- `OpenConfigFolder`: `std::process::Command::new("xdg-open").arg(&config_dir).spawn()`; ошибка → «Не удалось открыть файловый менеджер».
- `ReloadConfig`:
  1. если идёт capture — сначала `CancelCapture` (снять `switchfix.capture-pause`);
  2. `store.load()` → `app.cfg`, пересинхронизировать `mods_selection`/`mods_toggle`;
  3. записать `$TMPDIR/switchfix.reload` (token);
  4. статус: «Конфигурация перезагружена. Хоткеи — после перезапуска демона.»
  5. parse error → форму не менять, «Ошибка перезагрузки: {e}».
- Подсказка в UI: путь к config / maps (каталог уже открывается кнопкой).

### 4. `crates/switchfix-daemon/src/wiring.rs`

- `seed_default_maps()` при `build`.
- Начальный `ConversionSet` = `load_conversion_set()` (на первом запуске совпадает с `en_ru()`).
- `config_tx` остаётся — он и есть канал reload (watch уже читается в `CorrectionService::cfg()`).

### 5. `crates/switchfix-daemon/src/main.rs`

**Daemon loop** (2s arm, рядом с `switchfix.enabled`):
- если `switchfix.reload` изменился (token) → один раз:
  1. `store.load()` → при успехе `config_tx.send(cfg)`; при ошибке `warn!` и **не** трогать текущий watch;
  2. `service.replace_tables(load_conversion_set())`;
  3. `info!` / notify «Конфиг перезагружен».

**CLI:**
- `Command::Reload` — пишет флаг, печатает `reload signaled` (для скриптов).
- `Command::Settings` — `seed_default_maps()`, передать `config_dir` в `run_settings`.
- `Command::Convert` — `load_conversion_set()` вместо `ConversionSet::en_ru()`, чтобы правки карт влияли и на CLI.

## Edge cases

- Нет `~/.config/switchfix/` — создают `ensure_config` / `seed_default_maps`.
- Битый `config.toml` при reload — daemon держит прежний cfg (`warn!`); UI — ошибка, форма не сбрасывается.
- Битый map JSON — skip; ноль валидных → `en_ru()` + warn.
- Удалённые пользователем map-файлы **не** пересоздаются (seed only if dir empty) — удаление намеренное.
- Reload во время capture — сначала cancel (не перетирать hotkey-поля).
- `xdg-open` нет / не GUI — статус об ошибке.
- Latency reload ≤2s — как у `switchfix toggle`, приемлемо.
- **Save из UI перезаписывает TOML** и может затереть ручные правки — статус после Reload это объясняет; mtime-guard не в этом PR.

## Verification

```bash
cargo test --workspace
cargo build --release
./target/release/switchfix doctor
./target/release/switchfix settings
```

Ручной сценарий:
1. Settings → «Редактировать конфиг» → открылся `~/.config/switchfix/` (`config.toml` + `maps/`).
2. В `maps/en2ru.json` поменять пару → «Перезагрузить конфиг» → статус OK; `switchfix convert --text '…'` (после reload демона/CLI) учитывает map.
3. В `config.toml` добавить app в `behavior.terminal_apps` → Reload → терминальный путь (Ctrl+A / Ctrl+K / Ctrl+Shift+V) для нового id **без** рестарта.
4. Сменить хоткей → Save → сообщение о рестарте (как сейчас).
5. `RUST_LOG=debug` daemon: `Конфиг перезагружен` один раз на флаг.
6. `switchfix reload` из терминала — тот же эффект.
